# 정령의 숲 — 중간 서사 제작 (Bit 1 · Bit 3 · Bit 2)

- **프로젝트**: 정령의 숲 (Spirit Grove) — 브라우저 크리처 수집형 RPG
- **작성일**: 2026-08-04
- **선행**: 1단계 관문/장소 표찰(`d1c0a48`), 2단계 아침 기상 시퀀스, 3단계 Bit 0(목표 트래커 재배선)
- **이번 범위**: `outputs/strategy/2026-08-04_spirit-grove_narrative-strategy.md`의 Bit 1 → Bit 3 → Bit 2를 실제 코드에 반영
- **원칙 준수**: 트레이너 팀 구성·레벨·학습셋·종족값 변경 없음. 대사·연출·컷신만 추가/수정. `src/index.html` 소스만 편집, `dist/`는 빌드 산출물.

---

## 1. 제작 목표

1. **Bit 1** — 라이벌 카이 1차전에 개인적 동기(스승님 실종)를 심어, 4연전이 "경쟁"에서 "동행"으로 읽히도록 하고 V4의 기존 결말 대사("…졌다. 완전히. 가, 군주를 꺾어. 네가 이 숲을 지킬 자야, 친구.")와 자연스럽게 이어지게 한다.
2. **Bit 3** — 호수 전설전(수룡왕) 직전에 "왜 전설을 잡아야 하는가"와 "그다음 제단으로 간다"는 안내를 짧은 대사로 심는다.
3. **Bit 2** — 깊은 숲(region 3) 최초 진입 시, 체육관2 관장 다온의 outro("누군가 힘을 빨아먹고 있어")를 플레이어가 눈으로 목격하는 2쪽짜리 미니 컷신을 신설한다.

## 2. 적용 전략

전략 문서의 우선순위(Bit 0 → Bit 1 → Bit 3 → Bit 2)를 그대로 따름. Bit 0은 이전 세션에서 이미 완료(목표 트래커가 `4뱃지 → 전설 → 숲의 군주 → 정령 리그 → 도감` 순으로 재배선됨). Bit 5(견습 트레이너 세계관)는 전략상 보류 대상이라 이번엔 손대지 않음.

## 3. 크리에이티브 방향

- Bit 1: 카이의 동기를 "스승님이 인장이 옅어진 뒤 소식이 끊겼다 → 그 흔적을 쫓아 숲에 들어왔다"로 설정. 이 설정은 (a) 기존 V4 outro의 "군주를 꺾어… 네가 이 숲을 지킬 자야"라는 대사가 왜 카이 입에서 나오는지 설명해주고 — 카이도 처음부터 인장/군주 문제를 알고 있었다는 개연성이 생김 — (b) 4연전 내내 "누가 세냐"가 아니라 "같은 목표를 향해 가는 두 사람"이라는 서브텍스트를 깐다.
- Bit 3: 호수 제단 자체가 배로 접근하는 섬처럼 사방이 물로 막힌 구조라, "각오를 다지는 짧은 독백형 팻말" 톤으로 작성(기존 SIGN_MSG/제단 순례자 대사와 톤 일치). Bit 0으로 이미 "전설 다음은 숲의 군주"가 확정되어 있으므로, 대사가 그 다음 목적지를 직접 언급하도록 함.
- Bit 2: 새로 정보를 만들지 않고, 이미 존재하는 다온의 outro(1156행)와 학자 NPC의 앰비언트 대사(1206행, 정확히 region 3 안쪽 y=29에 배치됨)를 "장면"으로 승격. 1페이지는 뒤틀린 길·불안한 야생 정령의 눈, 2페이지는 옅어지는 빛과 그것을 삼키는 그림자 — STORY_INTRO 2페이지의 "빨아먹는 그림자" 시각 모티프(보라색 `#b07fd1` 촉수, 붉은 크랙)를 재사용해 톤 일관성을 유지.

## 5. 제작 명세 — 무엇을 어디에 넣었는가

### Bit 1 — 라이벌 카이 1차전 (`src/index.html`)

- `NPCS`의 `rival` 항목(`id:"rival",x:16,y:41`) — `lines`를 1페이지에서 2페이지로 확장:
  - p1(기존 유지): `"라이벌 카이: 어이! 너도 정령 연구소에서 왔다며?"`
  - p2(신규): `"실은 스승님을 찾으러 이 숲에 들어왔어. 인장이 옅어진 뒤로 소식이 끊기셨거든. 누가 더 센지, 한 판 가려보자!"`
  - `linesAfter`(패배 후 재대화, 1p): 기존 문구에 동기 한 줄 추가 → `"라이벌 카이: 큭… 이번엔 운이 좋았어. 그래도 스승님 흔적 쪽엔 나도 가까워지고 있어. 위에서 다시 붙자!"`
- `TRAINERS.V`(전투 진입 시 뜨는 별도 대사):
  - `intro`: `"라이벌 카이가 씩 웃으며 앞을 막아선다! \"스승님도 이 길을 걸으셨어 — 물러설 수 없다고!\""`
  - `outro`: `"…제법인데? 나도 스승님 흔적을 쫓아야 해서 물러설 수 없어. 위에서 또 보자고!"`
- V2/V3/V4는 전략 지시대로 손대지 않음(V4는 이미 완성된 결말 대사라 그대로 둠 — 이번 수정으로 비로소 "왜 V4가 그렇게 말하는지" 개연성이 생김).

### Bit 3 — 호수 제단 진입 전 (`src/index.html`, `move()` 함수 내 `%` 타일 핸들러)

`%` 타일(수룡왕 제단)은 좌표가 코드에 하드코딩돼 있지 않고 `findTile("%")`처럼 런타임 결정 — **실측 결과 좌표는 (16,23)**(`node -e`로 `MAP_STR`를 직접 파싱해 확인). 사방이 전부 `~`(물)로 둘러싸인 섬 구조라 서핑으로만 접근 가능함도 함께 확인.

기존:
```js
if(tileAt(x,y)==="%"&&!G.indoor){ stopPath(); if(!G.lakeDone){ startLakeLegendary(); } else {...} return; }
```
수정 후 — 최초 접근 시에만 2페이지 대사를 보여주고, 대사가 끝나면 기존 `startLakeLegendary()`를 호출(콜백):
- p1: `"호수가 낮게 울린다… 이 물속엔 아주 오래된 힘이 잠들어 있다."`
- p2: `"이 힘을 얻어야 제단에서 군주와 나란히 설 수 있어. 각오는 됐나?"`

두 번째 접근부터는(`G.lakeSignSeen===true`) 대사 없이 바로 `startLakeLegendary()`(기존 동작 유지, 재도전 시 매번 대사가 뜨지 않도록).

### Bit 2 — 깊은 숲 진입 컷신 (`src/index.html`)

- 신규 상수 `DEEPWOODS_INTRO`(COAST_INTRO 정의부 바로 앞에 배치) — 인라인 SVG 아트 2종(`_dwSVG1`: 뒤틀린 길 + 어둠 속 눈, `_dwSVG2`: 옅어지는 빛을 삼키는 그림자 촉수) + 대사 2쪽:
  - p1: `"길이 자꾸 뒤틀린다. 그늘 속에서 낯선 눈들이 이쪽을 살피다 이내 숨는다 — 정령들도 뭔가에 겁먹은 듯하다."`
  - p2: `"저 앞, 희미한 빛줄기가 검붉은 그림자에 서서히 삼켜진다. 다온의 말이 맞았다 — <b>누군가 인장의 힘을 빨아먹고 있다.</b>"`
- 트리거: `onArrived()`의 실외(outdoor) 분기, `announceRegion(G.pos.y)` 직후에 삽입:
  ```js
  if(region(G.pos.y)===3 && !G.deepwoodsSeen){ G.deepwoodsSeen=true; stopPath(); playStory(DEEPWOODS_INTRO,()=>{}); return; }
  ```
  region 3 = 깊은 숲(`y` 27~33, `region()` 함수 정의 그대로). `COAST_INTRO`/`G.coastSeen`과 동일한 "1회성 플래그 + `playStory`" 패턴을 그대로 복사해 사용.
- 실내(인테리어) 렌더 분기 안이 아니라 **실외 분기**에 넣었음을 명시(가이드가 경고한 "실내/실외 분기 혼동" 함정과는 별개 — 이 트리거는 오버월드 전용이라 인테리어 렌더 문제와 무관함을 확인했음).

### 세이브 상태 배선

`G.lakeSignSeen`(Bit 3), `G.deepwoodsSeen`(Bit 2) 두 플래그를 `freshState()`·`serialize()`·`deserialize()` 3곳에 모두 추가(`coastSeen`과 동일한 위치·패턴). Playwright로 `serialize()`→`deserialize()` 왕복 후 두 플래그가 보존되는 것까지 확인함(5장 참조).

## 6. 실측 — 라이벌 카이 4연전이 실제로 걸리는가

**결론: 걸리지 않는다. 4명 모두 회피 가능하다.**

- `rival`/`rival2`/`rival3`/`rival4`는 `t1~t21`을 포함한 `NPCS` 배열의 다른 모든 트레이너와 마찬가지로 `dir`/`range`(시야 감지) 속성이 없다. 이 저장소에서 시야 감지를 가진 유일한 NPC는 `duo`(`dir:"down",range:2`) 하나뿐이며, 나머지는 전부 "제자리에 서서 통행을 막는 장애물"이다.
- `walkable()`이 NPC가 서 있는 정확히 그 1칸만 비보행으로 막는다. 전투는 **플레이어가 그 칸을 마주 보고 상호작용 키(A/Enter)를 눌러야만** 시작된다(`interact()` → `talkNPC()`). 걸어서 부딪히기만 하면(`move()`) 벽에 부딪힌 것처럼 방향만 바뀌고 전투는 걸리지 않는다(`move()`의 거대한 타일 분기에 NPC_AT 케이스가 없음을 코드로 확인).
- `MAP_STR`을 직접 파싱해 BFS로 검증: 라이벌 4명의 좌표 `(16,41)/(20,37)/(21,29)/(19,13)`를 **동시에 전부 벽으로 막아도** 마을(y=48 인근)에서 제단/리그 구역(y=9~10 인근)까지 760개 타일이 여전히 연결돼 있다(`node -e`로 walkable 격자 BFS, 스크립트는 임시 파일로 실행 후 폐기). 즉 네 명 다 넓은 초원/숲 지형 위에 서 있을 뿐, 통로를 좁히는 1칸짜리 병목이 아니다(개별 인접 walkable 칸 수도 각 2~4개로, 우회로가 항상 존재).
- 목표 트래커(`currentGoal()`)는 좌표 안내만 하고 자동 이동(오토런) 기능이 없어, 이 부분에서 강제로 라이벌과 마주치게 만드는 장치도 없다.
- **함의**: 전략 문서 5장이 예상한 대로 Bit 1의 "4연전 전원이 guaranteed에 가깝다"는 전제는 성립하지 않는다. 다만 이 4연전은 마을→제단으로 가는 메인 경로 근처(각 지역 진입로 부근)에 배치돼 있어 완전 무작위 위치는 아니고, 트래커를 보며 걷는 표준 플레이 동선상 시야에 들어올 가능성 자체는 낮지 않다(실측하지 못한 부분 — 8장 참조). 이번 수정은 "만난 플레이어에게는" 개연성을 준다는 최소 보장으로 가치가 있으나, "전원이 반드시 만난다"는 강한 임팩트 근거로는 쓸 수 없다는 점을 기록해둔다.

### 실제 화면 노출 확인 (Playwright, 실입력 기준 — "정의만 있고 안 뜨는" 함정을 피하기 위해 필수로 수행)

임시 스크립트(`scratchpad/verify_bits.js`, 저장소 밖 — 커밋 대상 아님)로 타이틀이 아닌 `SG.setG()`로 상태를 주입한 뒤, **실제 방향키/Enter 키 입력**으로 각 비트를 발동시켜 확인:

- **Bit 1**: `(16,40)`에 배치 → `ArrowDown`(라이벌을 바라봄) → `Enter`(상호작용) → NPC 대사 1p("어이! 너도…") → 2p("실은 스승님을…") 확인 → 대화 종료 후 `TRAINERS.V.intro`("스승님도 이 길을…")가 별도 페이지로 이어짐 → 대화 종료 후 `G.inBattle===true && G.trainer.key==="V"` 확인. **전 구간 정상 노출.**
- **Bit 3**: `(16,22)`(물)에 서핑 상태로 배치, 4뱃지 보유 → `ArrowDown`(제단 진입 시도) → 대화창 뜸 → 1p("호수가 낮게 울린다…") → 2p("제단에서 군주와 나란히…") → 대화 종료 후 `G.inBattle===true`(수룡왕전 시작) 확인. **정상 노출.**
- **Bit 2**: `(14,34)`(숲, region 2)에 배치 → `ArrowUp`(region 3 진입) → `storyOverlay`가 열리고 1p("길이 자꾸 뒤틀린다…") 노출 → "계속" 클릭 → 2p("…빨아먹고 있다.") 노출 → `G.deepwoodsSeen===true` 확인 → 지역을 나갔다 다시 들어가도 컷신이 재생되지 않음(중복 방지) 확인. **정상 노출.**
- 세 시나리오 모두 브라우저 런타임 에러 0건.
- `serialize()`→`deserialize()` 왕복 후 `lakeSignSeen`/`deepwoodsSeen` 두 플래그가 보존되는 것도 별도로 확인(세이브/로드 후 컷신 재재생 방지).

## 8. 미확정 사항

- 라이벌 4연전이 "표준 플레이 동선상 실제로 눈에 얼마나 자주 들어오는가"(시야 반경 안에 들어오는 빈도)는 이번에도 실측하지 못했다. BFS로 확인한 것은 "강제 통과 지점이 아니다"까지이며, 정성적 도달률(몇 %의 플레이어가 실제로 4번 다 싸우는지)은 플레이 로그나 몽키 퍼즈 없이는 알 수 없다. 향후 사이클에서 값어치를 확인하려면 `duo`처럼 `dir`/`range`를 부여해 시야 감지형으로 바꾸는 방안을 검토 후보로 남긴다(단, 이는 전략적 결정이라 임의로 적용하지 않았다).
- Bit 3 대사는 `%` 타일이 서핑으로만 닿는 구조라는 것을 실측으로 확인했지만, 서핑 도구(`hasSurf`)를 얻기 전에 이 타일에 접근할 경로가 있는지는 본 작업 범위 밖이라 별도 확인하지 않았다(기존 `startLakeLegendary()` 로직 자체를 변경하지 않았으므로 게이팅에는 영향 없음).
- Bit 5(견습 트레이너 세계관 보강)는 전략 문서가 보류로 지정한 항목이라 이번 범위에서 제외했다.

## 9. 다음 제작 단계

1. (선택) 라이벌 도달률을 실측하고 싶다면 몽키 퍼즈/자동 완주 봇 로그에 트레이너 키 `V`/`V2`/`V3`/`V4` 격파 여부 카운터를 추가.
2. Bit 5(견습 트레이너 세계관) 착수 시 `TRAINERS["7"]`~`["f"]`의 intro/outro 문자열만 교체하면 되므로 낮은 리스크로 이어서 진행 가능.
3. `npcAmbient()` 랜덤 앰비언트 풀에 이번 사이클에서 다루지 않은 진행도 반영 서사를 추가하는 안은 전략 문서 4장에 후보로 남아 있음.
