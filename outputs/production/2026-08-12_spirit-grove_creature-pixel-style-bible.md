# 정령 픽셀 아트 스타일 바이블 (86종 공통 규격)

작성 2026-08-12 · 대상 `assets/art/creatures/{id}.webp` (매니페스트 `paint` 86종)
연계 문서: 주인공 규격 `2026-08-06_spirit-grove_hero-pixel-art-prompts.md` · NPC 규격 `2026-08-11_spirit-grove_npc-sheet-prompts.md`

## 0. 왜 만드나 (한 줄)

오버월드의 **주인공·NPC는 16비트 픽셀**인데 전투/도감의 **정령 86종만 글로시 페인터리 일러스트**라 한 화면에서 화풍이 갈린다. 정령을 같은 픽셀 계열로 다시 뽑아 **한 세계로 읽히게** 한다.

이 문서는 86종 전부에 적용되는 **불변 규격**이다. 종별 디테일(색·형태·모티프)은 Phase별 프롬프트 문서가 담는다.

---

## 1. 렌더링 사실 (코드에서 확인 — 프롬프트보다 먼저 알아야 할 것)

정령은 주인공과 **렌더 경로가 다르다.** 이걸 알아야 규격이 맞는다.

| 항목 | 사실 | 출처 |
|---|---|---|
| 주입 | `creatureVisual(id)` → `<img class="cart" src="…creatures/{id}.webp">` | `src/index.html:4539` |
| 보간 | `img.cart`·`.sprite` 둘 다 `image-rendering:pixelated` **이미 걸림** | `src/index.html:109,214` |
| 빌드 | `build.py`가 `paint` 86종 전부를 `assets/art/creatures/{id}.webp`로 자동 인라인 | `scripts/build.py:30` |
| 전투 표시 크기 | 내 정령 `.sprite.me` **118px** · 상대 `.sprite.foe` **104px** (정사각, `object-fit:contain`) | `src/index.html:215-216` |
| 팔로워 | 오버월드 동행 정령도 `PAINT_ART` 사용, 캔버스 `drawImage`는 최근접(08-07 처리됨) | `followerDataURL` |

**→ 정령은 코드 변경이 0이다.** 주인공은 캔버스에 그려 `heroDrawSpec` 로직이 필요했지만, 정령은 `<img>` + CSS `pixelated`라 **파일만 덮으면** 픽셀로 나온다. 매니페스트도 안 건드린다(ids가 이미 `paint`에 있음).

### ⚠️ 그래서 나오는 규격 제약 두 가지
1. **화면 표시가 104~118px다.** 논리 해상도를 여기에 맞춰야 주인공(64px)과 **도트 굵기(화면상 도트 하나의 크기)가 같은 계열**로 보인다. → 논리 **96px**를 기본값으로 잡는다(§3).
2. **정사각 + `object-fit:contain`이다.** 캔버스는 반드시 **정사각**, 정령은 **중앙 정렬**(주인공처럼 발을 아래 끝에 붙이지 않는다 — 전투에서 정령은 떠 있다).

## 2. 불변 스타일 규칙 (주인공·NPC와 동일 계열)

주인공·NPC 도트와 **같은 화면에서 형제로 보이게** 하는 최소 조건이다. 하나라도 어기면 다시 튄다.

- **하드 1px 어두운 외곽선.** 캐릭터 도트가 이걸 쓴다. 정령도 같은 굵기·같은 톤(순검정 아님, 어두운 종색).
- **플랫 셀 셰이딩, 재질당 음영 최대 2단.** 그라디언트·에어브러시·부드러운 블렌딩 금지.
- **안티에일리어싱 금지 · 디더링 금지.** 경계는 딱 끊는다(피부·몸통 면에 반투명 도트 없음).
- **제한 팔레트.** 종당 **24색 이내**(효과광 포함). 캐릭터가 12~16색이라 정령은 형태가 커서 24까지 허용.
- **완전 투명 배경.** 배경판·프레임·카드·바닥원·글로우 배경 전부 금지.
- **구운 그림자 없음.** 전투에서 정령은 떠 있어 그림자가 없다(파이프라인이 반투명 알파를 제거한다).
- **크리스프 스퀘어 픽셀, 격자 정렬.** 반픽셀·흐린 경계 없음.

### 페인터리에서 버리는 것 (지금 아트의 특징 = 제거 대상)
현재 86종은 전부 이 특징을 갖고 있고 **전부 버린다**: 부드러운 셀 그라디언트, 림라이트/발광 안개, 반투명 광채, 물/불의 반투명 파티클, 유리질 반사(이슬방울), 소프트 그림자. → 픽셀에서는 **단단한 색면 + 1~2단 음영 + 하드 하이라이트 도트**로 번역한다.

## 3. 규격표 (파이프라인에 넣기 전 확정)

| 항목 | 값 | 이유 |
|---|---|---|
| 논리 해상도 | **96 × 96 px** (기본) | 표시 104~118px에 ≈1:1 → 주인공 도트와 같은 굵기. Phase 1로 확정 |
| 대안 | 64px(더 굵게) / 80px(중간) | 96이 너무 매끈하면 낮춘다. **Phase 1 스크린샷으로 락** |
| 파일 | `assets/art/creatures/{id}.webp` (lossless webp) | `paint` 키와 1:1, id는 `dex.js`의 `id` |
| 배경 | 완전 투명 | |
| 그림자 | 없음 | |
| 캔버스 | **정사각 · 정령 중앙** · 사방 여백 소량 | `object-fit:contain`, 전투 애니(부유·런지)에 잘리지 않게 |
| 시점/방향 | **3/4 정면, 화면 왼쪽(정령 기준 오른쪽)으로 살짝 튼 자세** | 기존 86종 관행과 동일 → 코드의 `.me` 좌우 반전이 자연스럽게 맞는다 |
| 포즈 | **정지 배틀 포즈 1장**(걷기 프레임 없음) | 정령은 시트가 아니라 단일 스프라이트 |
| 외곽선 | 어두운 종색 1px | |
| 팔레트 | 종당 24색 이내 | |

### ⚠️ 방향을 왜 "화면 왼쪽으로 살짝"으로 고정하나
기존 86종이 거의 다 **화면 왼쪽(그 정령의 오른쪽)을 향해** 그려져 있다(파라꼬·파라울·무르꼬·무르롱·새록꼬 전부). 코드는 내 정령(`.sprite.me`)을 상황에 따라 좌우 반전해 상대를 마주 보게 한다. 방향을 뒤집으면 반전 로직과 어긋나 **내 정령이 등을 돌린 것처럼** 보인다. → 신규 픽셀도 **같은 방향**으로 통일한다. 완전 측면은 금지(전투에서 앞모습이 안 보임), 완전 정면도 지양(반전 시 무표정) — **3/4**가 정답.

## 4. 진화 라인 연속성 (라인은 "같은 존재의 성장"으로 읽혀야 한다)

정령은 대개 3단 진화한다. 픽셀로 다시 뽑을 때 **각 단계를 따로 디자인하면 남남처럼** 보인다. 규칙:

1. **시그니처 색을 유지한다.** 라인 전체가 같은 주색+보조색 팔레트 가족을 공유한다.
   - 예) 파라꼬 라인 = 주황+크림+불꽃 / 무르꼬 라인 = 하늘색+크림+짙은파랑 / 새록꼬 라인 = 라임그린+크림+갈색나무.
2. **핵심 모티프를 계승·발전시킨다.** (불꼬리 → 큰 불갈기+불꼬리 → 다수의 불꼬리·황금장식 / 잎새싹 → 잎갈기 → 나무정령의 잎수염).
3. **아키타입 전환은 허용한다.** 귀여움(1단) → 날렵함(2단) → 위엄(3단)의 실루엣 변화는 자연스럽다. 단 **색·모티프가 다리를 놓아야** 한다.
4. **크기 인상.** 3단은 프레임을 더 채우고 디테일·장식을 늘린다(황금 발찌·보석·문양 등 기존 아트의 상징 요소를 도트로 계승).

프롬프트 문서는 라인별로 **"계승 항목"을 명시**한다(어떤 색·모티프가 반드시 이어져야 하는지).

## 5. 페인터리 → 픽셀 번역 치트시트 (효과별)

| 페인터리 원본 | 픽셀 번역 |
|---|---|
| 반투명 불꽃 파티클(파라꼬 꼬리) | **불투명 색면 불꽃** — 진주황→주황→노랑 2~3단, 뾰족한 도트 실루엣, 하드 하이라이트 |
| 물의 반투명 스플래시(무르꼬) | 하드 엣지 물결·물방울 도트, 흰 하이라이트 1~2도트 |
| 유리질 투명 몸(이슬방울) | **반투명 대신 밝은 하늘색 몸 + 흰 하이라이트 도트 + 어두운 테두리**로 "투명함"을 암시 |
| 소프트 림라이트 | 실루엣 한쪽 가장자리에 밝은 색 1px 라인 |
| 부드러운 털 그라디언트 | 2단 색면 + 몇 개의 방향성 도트로 털결 암시 |
| 금속·보석 광택(파라온·무르칸) | 하드 하이라이트 도트 + 어두운 면, 반짝임은 흰 십자 픽셀 1개 |

## 6. 생성 → 반입 파이프라인 (검증된 경로, 주인공·NPC와 동일 구조)

```
① 생성기로 정령 픽셀 아트 생성 (프롬프트 문서 사용)
② art_inbox/creatures/{id}.png|webp 로 저장  (파일명 = dex.js의 id)
③ python3 scripts/make_creature_art.py           # 배경제거 → 그림자제거 → 정사각중앙 → 도트화
④ python3 scripts/build.py                        # PAINT_ART 자동 재생성 (매니페스트 수정 불필요)
⑤ 전투/도감 스크린샷으로 주인공과 같은 화면에서 화풍 확증
```

- ⚠️ **원본을 덮어쓰지 않는다.** 입력 `art_inbox/creatures/`, 출력 `assets/art/creatures/`. 페인터리 원본은 `art_inbox/creatures_src/`에 86종 전부 보존돼 있다(되돌리려면 거기서 복사).
- ⚠️ 파일명이 틀리면 조용히 폴백한다 → 스크립트가 `dex.js` id 목록과 대조해 **미상 이름을 경고**한다.
- ⚠️ 생성기는 투명 배경·격자를 잘 못 지킨다 → 파이프라인이 flood-fill 배경 제거 + 팔레트 정리로 보정한다. 그래도 이상하면 Aseprite에서 한 번 정리.

## 7. 받은 뒤 공통 검수 체크리스트

- [ ] 배경 완전 투명 (배경판·프레임·바닥원 없음)
- [ ] 구운 그림자 없음
- [ ] 정사각 캔버스에 정령 **중앙**, 사방 여백 소량 (전투 부유 애니에 안 잘림)
- [ ] **3/4 정면, 화면 왼쪽으로 살짝** (기존 86종과 같은 방향)
- [ ] 1px 하드 외곽선 · 셀 셰이딩 2단 이내 · AA/그라디언트/디더 없음
- [ ] 팔레트 24색 이내
- [ ] **진화 라인이 같은 색·모티프 가족**인가 (라인을 나란히 놓고 확인)
- [ ] 주인공·NPC 도트와 **같은 굵기·같은 계열**로 보이는가 (같은 화면 스크린샷)
- [ ] 원종의 정체성(색·특징)이 유지돼 **어떤 정령인지 알아볼 수 있는가**

## 8. 전제 / 미확정

- **전제**: "다시 만든다"는 재생성이다 — 기존 페인터리를 자동 축소하는 방식(`pixelize_creatures.py`)은 인수인계상 두 번 "모자이크"로 실패했고 이 문서는 그 길을 쓰지 않는다.
- **미확정(Phase 1로 락)**: 논리 해상도(96 vs 80 vs 64) · 팔레트 상한(24가 적정인지) · 도트 굵기가 캐릭터와 정확히 붙는지. 12종 스크린샷을 보고 확정한 뒤 나머지 74종에 적용한다.
- **범위**: 전설 5종(glaciarch·aqualord·shadowlord·dawnguard·dawnwyrm)도 `paint`에 있어 같은 규격을 따르되, 위엄·스케일을 최상단으로 잡는다. Phase 2 이후.
